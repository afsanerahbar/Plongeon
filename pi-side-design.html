Pi-Side Capture Design

Components, class relationships, runtime call sequences, and build order for the Raspberry Pi half of the diving foot-placement tracker — capture a frame, find four markers (heel and toe on each foot), convert to board millimeters and foot angle, then package and sync each attempt.

Components

Seventeen classes — six data objects, one interface with two implementations, seven behavior classes, and one orchestrator — plus two entry scripts that wire them together.

orchestratorCaptureService

run(), stop(). Coordinates every class through injected dependencies; syncs and refreshes the session on a background thread.

scriptmain.py

Composition root: loads calibration, builds every object, injects them into CaptureService. Run by systemd.

scriptcalibrate.py

Operator tool: lens calibration from checkerboard photos, board calibration from reference markers, then save.

interfaceFootDetector

detect(frame) → list[FootKeypoints]. Empty list when no foot is found, so implementations are interchangeable.

implements FootDetectorMarkerDetector

Primary. Finds the four DICT_4X4_50 markers; each marker's refined center becomes a heel or toe point.

implements FootDetectorPoseDetector

Cross-check. BlazePose heel and foot_index landmarks; position only.

geometryCalibrationManager

Lens correction + homography. to_world(keypoints) converts heel and toe to mm, then computes the angle in board coordinates.

persistenceCalibrationStore

save() / load() calibration data. Used only by the two scripts.

captureCameraCapture

Picamera2, 1440×1080, short exposure. start(), stop(), get_frame() → Frame.

event logicAttemptEventDetector

Takeoff zone in board mm. Both feet in the zone, then gone → AttemptTrigger with the last-contact frame.

image outputThumbnailGenerator

generate(trigger) → thumbnail with heel/toe points, foot lines, and angles drawn on.

local storageLocalBuffer

SQLite. save(), get_unsynced(), mark_synced() — nothing lost when Wi-Fi drops.

networkCloudSyncClient

The only class that talks to Supabase: uploads, thumbnails, fetch_active_session().

dataFrame

image, captured_at.

data · pixelsFootKeypoints

foot_side, heel_px, toe_px, confidence, source.

data · board mmFootMeasurement

foot_side, heel_mm, toe_mm, angle_deg, confidence, source.

dataAttemptTrigger

frame, keypoints {left, right}, measurements {left, right}.

dataSessionContext

session_id, diver_id, dive_type, fetched_at — set by the coach in the app.

dataAttemptRecord

attempt_id, captured_at, session/diver/dive (null = unassigned), left_foot, right_foot, thumbnail_path.

Class diagram

CaptureService depends on the FootDetector interface, never on a concrete detector. Detectors only know pixels; CalibrationManager is the single place pixels become board millimeters and angles.

Call sequences

Three flows: the per-frame loop, what happens once an attempt is detected plus the background sync, and calibration followed by startup.

Build order

Bottom-up: prove each piece on its own, pass the bench accuracy test before any attempt logic exists, and wire CaptureService together last, when every dependency it receives already works.

Milestone 1 — see a frame, measure a foot on the bench
  1. 1Frame + CameraCaptureSet the IMX296 lines in config.txt, check with rpicam-hello, then grab frames through Picamera2.
  2. 2CalibrationManager (lens) + CalibrationStore + calibrate.pyCheckerboard photos at a desk; confirm straight lines come out straight after correction.
  3. 3FootKeypoints + FootDetector + MarkerDetectorA printed sheet with the four markers: confirm the IDs map to the right heel/toe and the centers are stable frame to frame.
  4. 4CalibrationManager (board) + FootMeasurement + to_world()A printed grid with known points stands in for the board; check millimeter readings against a ruler.
  5. 5Bench accuracy testPrinted foot template rotated in 1° steps and moved to known positions. Pass: angle error under 1°, position within the coach's tolerance. Don't continue until it passes.
Milestone 2 — recognize an attempt
  1. 6AttemptTrigger + AttemptEventDetectorFeed scripted sequences of fake measurements (feet in the zone, then gone) and check one trigger per attempt.
  2. 7ThumbnailGeneratorOne saved frame and a fake trigger; confirm the overlay lines up with the feet.
  3. 8AttemptRecord + SessionContextPlain data classes, quick once the measurements exist.
Milestone 3 — persist and sync
  1. 9LocalBufferSave and read back fake records in a throwaway SQLite file.
  2. 10Supabase tables + row-level security + CloudSyncClientUpload dummy records and thumbnails; read a session row created by hand. Keep the key in .env, out of git.
Milestone 4 — integrate and deploy
  1. 11CaptureService + main.pyWire everything together, with sync and session refresh on a background thread. Bugs here are almost always wiring, since every part was tested alone.
  2. 12systemd service + poolside trialStart on boot, restart on crash. First trial only with pool and coach approval, and with the boom clear of the diver's path.
  3. 13PoseDetectorThe markerless cross-check, added once the primary path works end to end.
